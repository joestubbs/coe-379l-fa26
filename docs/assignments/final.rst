Final Project 
=============

**Date Assigned:** Tuesday, Nov. 2, 2026

**Due Date:** Monday, Dec. 10, 5 pm CST. (The day of the final exam for our class).
**Note:** The final version of the project is due at this time, but see below for 
intermediate deadlines. 

**Description:** 
The final project is open-ended, allowing you to propose an idea for a project that is of interest 
to you. You may incorporate any of the techniques or ideas presented in the lectures. You may 
also choose to study and incorporate a published paper, a new ML technology, a new formal 
methods library, etc. Your project should have one significant AI/ML component and one FM component. 

**Group Assignment:**
Students can work in groups of up to five on this assignment. The
the roles and contributions of each student are required to be well defined. Additionally, 
there will be a question and answer portion, and all members of the group will be responsible 
for understanding all aspects of the project. You are allowed to talk to students in other groups 
about the project, but you are not allowed to copy code or any other deliverables for the project 
from students outside of your group. 

**Use of AI:**
You are allowed to use AI to help you develop ideas and code for the project, but if you use 
AI you must: 

1) be able to clearly explain all relevant aspects and details of the design and code; and 
2) clearly cite how you used it and what portions of the code were generated by AI. 

You **may not** use AI to write the final report.

Initial Proposal
----------------

Begin by writing an initial proposal for your project. The initial proposal has a maximum of 
2 pages in length, though you can include additional figures and/or data samples, etc., 
beyond the two pages, as necessary.

Include the following in your proposal:

* Introduction and topic and/or problem statement --- A short introduction and summary of the 
  goals of the project
* Data sources that will be used --- A reference to any datasets utilized in the project
* List of high-level methods, techniques and/or technologies that you are considering using. If developing an application, include a high-level architecture diagram. 
* Products to be delivered --- what are the primary deliverables for the project? This is what we will be grading
* Roles of each student in the group 

The initial proposal will be worth 10 points. Groups that do not submit the proposals by the due 
date will lose the 10 points and will still be required to get a proposal approved in order to 
submit the final project. Commit your initial proposal to your final project git repository.


Git Repository 
--------------
The project products should be saved into an organized git repository, similar to the way 
we have done the other projects. The initial proposal should be among the documents included 
in your git repository, and it should be there by the initial proposal due date 

Grading
-------
The final project will be graded as follows:

* 2 points --- Group sign up by deadline (Nov 10) Sign up Sheet (no partial credit for late sign ups)

* 10 points --- Proposal (due Nov 17)

   1. First draft submitted on time 
   2. Any required updates made within 1 week. 

* 20 points --- Project Concept 

 1. Does the project concept involve relevant machine learning topics, ideas and/or technologies? 
 2. Is the project useful and/or interesting?
 3. Is the project unique?

* 33 points --- Project Products 

 1. Do the products achieve the described goals?
 2. Are the products available (e.g., in a code repository)?
 3. Are the products well-documented?

* 35 points --- report/video and live Presentation and Q&A

 1. Does the the final report/video cover all sections?
 2. Is the writing/video easy to follow? (i.e., there is a logical progression of the presentation, 
    important details are not missing but we are not drowned in minutiae either, etc.)
 3. Are all sources referenced?

**Some Example Project Seed Ideas:**

QA assistant over scientific papers, engineering manuals, or documentation

* FM component: Typed claims, evidence requirements, source validation, optionally a Lean checker

LLM agent that manages files, schedules experiments, or interacts with APIs

* FM component: Verified preconditions, allowed state transitions, authorization policies

Agent that launches simulations, LLM calls, or computing jobs

* FM component: Formal budget accounting, resource limits, proof that authorized requests 
  cannot exceed a budget

Agent that attempts Lean proofs and repairs failures using compiler feedback

* FM component: Lean checks generated proofs; students analyze success and failure rates

ML model controls a simulated robot, vehicle, or other engineering system

* FM component: Runtime safety monitor that restricts unsafe actions
